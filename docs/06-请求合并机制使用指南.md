# 请求合并机制使用指南

## 概述

请求合并机制通过在短时间内收集多个独立的 API 请求，然后将它们合并为一次批量请求发送到后端，从而显著减少 HTTP 连接次数和降低网络开销。

## 架构概览

```
前端 (RequestBatcher)
  |
  | 1. enqueue() - 将请求加入队列
  | 2. 等待 50ms 收集窗口
  | 3. 去重并合并
  v
POST /api/batch/execute
  |
  | 4. 并行执行子请求 (最多 5 并发)
  | 5. 收集所有结果
  v
前端接收批量响应并分发结果
```

## 前端使用

### 基本用法

```typescript
import { getRequestBatcher } from '@/utils/requestBatcher'

// 获取实例 (单例模式)
const batcher = getRequestBatcher({
  windowMs: 50,       // 收集窗口: 50ms
  maxBatchSize: 10,   // 最大批次大小
  maxRetries: 2,      // 最大重试次数
  baseUrl: 'http://localhost:8000', // 后端地址
})

// 像普通请求一样使用，返回 Promise
const promise1 = batcher.enqueue({
  method: 'GET',
  path: '/api/tasks/1',
})

const promise2 = batcher.enqueue({
  method: 'GET',
  path: '/api/tasks/2',
})

// 等待结果
const [result1, result2] = await Promise.all([promise1, promise2])
console.log(result1.data) // { value: 1 }
console.log(result2.data) // { value: 2 }
```

### 支持所有 HTTP 方法

```typescript
// GET
batcher.enqueue({ method: 'GET', path: '/api/items' })

// POST
batcher.enqueue({
  method: 'POST',
  path: '/api/items',
  body: { name: 'new item' },
})

// PUT
batcher.enqueue({
  method: 'PUT',
  path: '/api/items/1',
  body: { name: 'updated' },
})

// DELETE
batcher.enqueue({ method: 'DELETE', path: '/api/items/1' })
```

### 请求取消

```typescript
// 取消特定请求
batcher.enqueue({ method: 'GET', path: '/api/test' })
batcher.cancel('request_id_here')

// 取消所有待处理请求
batcher.cancel('all')
```

### 工作流场景：批量查询任务状态

```typescript
// 工作流执行期间，同时查询多个任务状态
const taskIds = ['task-1', 'task-2', 'task-3']
const promises = taskIds.map((id) =>
  batcher.enqueue({
    method: 'GET',
    path: `/api/tasks/${id}/status`,
  })
)

const results = await Promise.all(promises)
results.forEach((res, i) => {
  console.log(`Task ${taskIds[i]}: ${res.status}`)
})
```

### 清理资源

```typescript
// 应用卸载时清理
import { destroyRequestBatcher } from '@/utils/requestBatcher'
destroyRequestBatcher()
```

## 后端 API 接口

### 批量执行接口

**POST** `/api/batch/execute`

#### 请求格式

```json
{
  "requests": [
    {
      "id": "req_001",
      "method": "GET",
      "path": "/api/tasks/1",
      "headers": { "Authorization": "Bearer xxx" },
      "body": null
    },
    {
      "id": "req_002",
      "method": "POST",
      "path": "/api/reports",
      "body": { "title": "月度报告" }
    }
  ]
}
```

#### 响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "results": [
      {
        "id": "req_001",
        "status": 200,
        "data": { "id": 1, "status": "completed" },
        "error": null
      },
      {
        "id": "req_002",
        "status": 201,
        "data": { "id": 2, "title": "月度报告" },
        "error": null
      }
    ]
  }
}
```

#### 错误响应

```json
{
  "results": [
    {
      "id": "req_003",
      "status": 404,
      "data": null,
      "error": {
        "code": "404",
        "message": "资源不存在"
      }
    }
  ]
}
```

### 接口特性

| 特性 | 说明 |
|------|------|
| 并行执行 | 子请求并行处理，最多 5 并发 |
| 错误隔离 | 单个请求失败不影响其他请求 |
| 超时控制 | 单个子请求超时 10 秒 |
| 批量限制 | 单次最多 20 个子请求 |

## 核心特性

### 1. 请求去重

同一批次中相同的方法+路径+请求体会被合并，避免重复请求。

```typescript
// 这两个请求会被合并为一个后端请求
batcher.enqueue({ method: 'GET', path: '/api/tasks/1' })
batcher.enqueue({ method: 'GET', path: '/api/tasks/1' }) // 去重
```

### 2. 自动重试

对网络错误和 5xx 服务器错误自动重试，最多 2 次。

```typescript
// 遇到 500 错误会自动重试
batcher.enqueue({ method: 'GET', path: '/api/flaky-service' })
```

不会重试的错误：
- 4xx 客户端错误（权限不足、资源不存在等）
- 业务逻辑错误

### 3. 时间窗口合并

```
时间轴:
|--[50ms 收集窗口]--|
  req1   req2   req3
          |
          v
      一次批量请求
```

- **默认窗口**: 50ms
- **立即刷新条件**: 队列达到 `maxBatchSize`

### 4. 错误级别隔离

```typescript
const p1 = batcher.enqueue({ method: 'GET', path: '/api/exist' })
const p2 = batcher.enqueue({ method: 'GET', path: '/api/missing' })

const r1 = await p1  // 成功
const r2 = await p2  // 抛出 "资源不存在"
```

## 性能对比

| 场景 | 单独请求 | 合并请求 | 优化 |
|------|---------|---------|------|
| 10 个状态查询 | 10 次 HTTP 连接 | 1 次批量请求 | ~90% 连接减少 |
| 5 个并行查询 | 5 次往返 | 1 次往返 | ~80% 延迟减少 |
