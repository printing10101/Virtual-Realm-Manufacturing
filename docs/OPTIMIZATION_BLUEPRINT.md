## 〇、执行摘要（TL;DR）

灵境制造要从"AI 工具"进化为"现象级平台"，核心路径是**"自进化 + 物理可信 + 工艺师协作 + 生态标准化"四位一体**。本蓝图把整个演进规划分为三层：

| 层级 | 名称 | 性质 | 状态 |
|------|------|------|------|
| **主引擎** | APT 自适应工艺孪生 | 数据飞轮 + 物理约束 + AI 推理 | 必须做 |
| **L1 增强层** | APT 能力补强 | 强化主引擎 | 必须做 |
| **L2 并行优化层** | 现状系统优化 | 8 项并行打磨 | 应做 |
| **L3 基础能力层** | 生态与商业基础设施 | 5 项长期建设 | 择机做 |

**一句话定义现象级**：

> **不是单点算法突破，而是"会学习的、懂物理的、可解释的、有人用的、有生态的"完整闭环。**

### 1.1 核心洞察

## 三、主引擎：APT 自适应工艺孪生

### 3.1 方向 1：车间数据底座
**目标：让 APT 拥有真实数据，不是模拟数据。**

#### 3.1.1 MTConnect / OPC UA 适配层
- 库：`mtconnect-python` / `OPC UA Python`
- 协议：HTTP / MQTT 双通道
- 采集字段：
  - 主轴：转速、扭矩、功率
  - 进给：实际/目标、位置
  - 振动（可选）：加速度传感器
  - 刀具：当前刀号、已加工时间
- 输出：时序数据 → TDengine / InfluxDB

#### 3.1.2 加工结果回灌
- **首件检验录入**：扫码 → 表单（尺寸/粗糙度/形位公差）
- **终检结果录入**：对接三坐标 / 影像仪
- **刀具寿命追踪**：领用 → 报废全程

#### 3.1.3 统一数据模型
```python
@dataclass
class MachiningRecord:
    machine_id: str

    process_plan: ProcessPlan

```

### 3.2 方向 2：工艺知识图谱（务实版）

#### 3.2.1 极简本体（4 类核心实体 + 4 类关系）

### 3.3 方向 3：数字孪生仿真引擎

#### 3.3.1 仿真模块清单
| 模块 | 输入 | 输出 | 算法 |
|------|------|------|------|
| 切削力预测 | 材料/刀具/参数 | 3D 力向量 | Kienzle 公式 + PINN 残差 |
| 温度场 | 同上 | 切削区温度 | FEA-Lite（PyTorch） |
| 振动/颤振 | 主轴/刀具刚性 | 稳定性极限 | 解析稳定性叶 + 神经网络 |
| 刀具磨损 | 累积参数 | 磨损量 | Archard 模型 + LSTM |
| 工件形变 | 切削力 + 装夹 | 形变云图 | 简化有限元 + 数据驱动 |
| 表面粗糙度 | 切削参数 + 振动 | Ra 预测 | 经验公式 + ML 修正 |

#### 3.3.2 PINN 物理约束实现
```python
class CuttingForcePINN(nn.Module):
    """物理约束的切削力预测网络"""
    def forward(self, params):
        return self.net(params)  # Fx, Fy, Fz
    
    def physics_loss(self, pred, params):
        fz_analytical = kienzle_force(params)  # 解析公式
        data_loss = MSE(pred, fz_actual)
        physics_residual = MSE(pred[:, 2], fz_analytical)
        return data_loss + 0.1 * physics_residual
```

### 3.4 方向 4：LNN + PINN + 贝叶斯（不是黑盒）

#### 3.4.1 三层推理架构
```
输入工艺任务
   ↓
[第 1 层] 任务路由
   - 高置信度（>0.9）→ LNN 直接预测
   - 中置信度（0.5-0.9）→ LNN + 物理校验
   - 低置信度（<0.5）→ 主动学习
   ↓
[第 2 层] 物理校验（仿真器 vs LNN）
   ↓
[第 3 层] 不确定性量化（贝叶斯 LNN）
```

#### 3.4.2 不确定性量化
```python
class BayesianLNN(nn.Module):
    def predict_with_uncertainty(self, x, n_samples=50):
        preds = torch.stack([self.forward_with_dropout(x) for _ in range(n_samples)])
        return preds.mean(dim=0), preds.std(dim=0)  # 置信区间
```

### 3.5 方向 5：主动学习闭环

#### 3.5.1 触发场景
| 场景 | 触发条件 | 动作 |
|------|---------|------|
| 新刀具 | 知识图谱无 | 工艺师输入推荐参数 |
| 新材料 | 知识图谱无 | 物理仿真 + 保守推荐 |
| 低置信度 | 贝叶斯置信度 < 0.5 | 列出 3-5 相似案例 |
| 仿真不一致 | LNN vs 仿真差 > 30% | 标记待人工审核 |
| 实测异常 | 实测 vs 预测差 > 阈值 | 进入再训练 |

#### 3.5.2 三种"提问"模式
- **被动记录**（99% 时间）：工艺师自己改参数，0 打扰
- **轻量提示**：工艺师选新刀具，半透明 tooltip
- **主动请求**：模型极低置信度时，模态对话框

#### 3.5.3 联邦学习（高级）
- 多工厂部署 → 不共享数据，只共享模型梯度
- 用 PySyft / Flower 框架
- **数据不出厂**原则下模型持续进步

### 3.6 方向 6：工艺师协作界面（透明决策 Co-pilot）

#### 3.6.1 决策透明化示例
```
[AI 推荐的切削参数]
  转速：3500 RPM | 进给：1200 mm/min | 切深：1.5 mm

💡 决策依据：
  • 历史 12 次类似加工（45 钢 / Φ10 立铣刀 / 型腔）
  • 平均表面粗糙度 Ra=1.6μm（合格）
  • 平均刀具寿命 85 分钟
  • 仿真预测：切削力 280N（< 机床刚性极限）

⚠️ 不确定性：
  • 主轴功率预测置信度 0.72（中等）
  • 建议首件加工后录入实际值
```

#### 3.6.2 实时 re-simulation
- 用户调整参数 → 立即重新仿真 → 立即显示新结果
- 仿真器 PyTorch 推理 < 100ms

#### 3.6.3 决策沉淀
- 工艺师每次"采纳/修改/拒绝" → 自动入审计日志
- **老师傅的隐性知识 = 数据资产**

### 3.7 方向 7：多模态工艺理解（务实版）

#### 3.7.1 优先级（与经验数据对齐）
| 模态 | 占比 | 难度 | 优先级 |

- 工艺卡片模板识别：自训练小模型

## 四、L1 增强层（APT 能力补强）

### 4.1 数字孪生可视化的二次飞跃
- **多窗口 3D 协同视图**：设计图 / 实际加工 / 应力云图 / 刀轨回放
- **剖面视图**：选中特征 → 自动剖切 → 显示物理量
- **AR 叠加**（实验性）：摄像头 + WebXR，把仿真贴到真实工件
- **技术选型**：3D Tiles / glTF + Three.js 着色器 + LOD

### 4.2 APT 质量度量（Self-Metric）
四级指标体系：
```
L1 基础（能用）: 方案成功率 / 语法正确率
L2 工艺（能造）: 切削参数合规率 / 碰撞率 / 刀具寿命偏差
L3 效率（造得快）: 规划耗时 / 试切次数 / 单件工时
L4 经济（造得便宜）: 单件成本 / 刀具成本占比 / 设备 OEE
```
- **必做**：APT 启动前先量化基线（50 个历史工件）
- **持续监测**：Grafana 仪表盘 + 飞轮状态评估

### 4.3 知识图谱运维体系
- **版本化与回滚**：`.vkg/` Git 管理 + PR Review
- **可信度评分**：`confidence_score: float, evidence_count: int, last_validated: date`
- **健康检查**：孤立实体 / 关系矛盾 / 老旧数据告警
- **贡献者体系**：隐式贡献 + 显式修正 + 排行

### 4.4 主动学习的工艺师体验
- **三种提问模式**：被动 / 轻量 / 主动（99% 被动）
- **提问即上下文**：不是"你推荐什么"，而是"历史 3 个类似案例 + AI 建议"
- **信任建模**：跟踪采纳率 → 减少对低信任用户的主动提问
- **拒绝被绑架**：任何时候可跳过 AI 建议

| 版本 | 包含 | 价格 |
|------|------|------|
| **Community** | 核心功能、单用户 | 免费 |
| **Pro** | 多用户、协作、云同步 | ¥XXX/年/人 |
| **Enterprise** | 数据闭环、APT 主动学习、联邦学习、SLA | 按需 |
| **行业版** | 垂直知识图谱、合规认证 | 高客单价 |

**关键原则**：
- **数据闭环、APT 主动学习、垂直知识图谱** → 付费版
- **核心引擎、DXF/STEP、后处理** → 开源（建立信任）
- **企业级特性**（多机床协同、合规）→ 按席位/工厂收费

## 七、实施路径与依赖关系

### 7.1 严格依赖链（必须按序）
```
数据底座（L1.1）→ 协议适配（L1.8）→ 知识图谱 V1（L1.2）
     ↓
仿真引擎（L1.3）→ 贝叶斯 LNN（L1.4）→ 主动学习（L1.5）
     ↓
闭环飞轮启动
```

### 7.2 弱依赖（可全员并行）
```
错误处理（L2.2）  ┐
测试覆盖（L2.3）  │
文档体系（L2.4）  ├─→ 与 APT 同步推进
DevOps（L2.5）    │
性能优化（L2.7）  │
UX 最后一公里（L2.8）┘
```

### 7.3 商业依赖（生态形成后）
```
.vrm 规范（L3.1）  ← 需 API 稳定
插件 SDK（L3.2）   ← 需规范稳定
社区体系（L3.3）    ← 需用户基数
合规认证（L3.4）    ← 需商业化目标
商业化（L3.5）      ← 需核心价值验证
```

### 7.4 三个并行轨道（推荐执行方式）

#### 轨道 1（最优先）：APT 核心
按"先加法后融合"分阶段做。

#### 轨道 2（持续进行）：L2 持续优化
选**最影响体验的 2-3 项**先做：
- 错误处理与可观测性
- 测试覆盖
- 文档体系

#### 轨道 3（择机启动）：L3 基础能力
等核心引擎稳定后启动：`.vrm` 规范、合规、商业化。

## 八、关键决策点

| 决策项 | 候选 | 推荐 | 理由 |
|--------|------|------|------|
| 时序数据库 | TDengine / InfluxDB | **TDengine** | 国内主流、压缩比高、SQL 兼容 |
| 图存储 | NetworkX / Neo4j / NebulaGraph | **NetworkX 起步** | 先验证价值再升级 |
| 物理仿真 | PyTorch + PINN / NumPy 解析 | **PyTorch + PINN** | 灵活、可微、与 LNN 统一栈 |
| 不确定性 | MC Dropout / Pyro | **MC Dropout** | 轻量、与现有栈一致 |
| 主动学习 | 自研 / modAL | **自研** | 简单场景够用 |
| PDF 解析 | PyMuPDF + Camelot / Unstructured | **PyMuPDF + Camelot** | 中文支持好 |
| MTConnect | mtconnect-python / 自研 | **mtconnect-python** | 成熟开源 |
| 联邦学习 | Flower / PySyft | **Flower** | 工业级 |

## 九、风险控制

### 9.1 高风险点及应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 贝叶斯 LNN 推理变慢 | 高 | 中 | 渐进切换 + fallback |
| 主动学习打断主流程 | 中 | 高 | 99% 被动 + 工艺师可跳过 |
| PINN 物理约束与 LNN 数据驱动冲突 | 中 | 高 | 并行运行 + 标记差异 |
| 数据底座投入大 | 中 | 高 | 先加法（TDengine）后融合 |
| 商业化路径与开源冲突 | 中 | 中 | 清晰边界（核心开源 / 闭环付费） |

### 9.2 必须避免的坑

- ❌ **不要先改 LNN**（高风险、低短期收益）
- ❌ **不要追求一步到位闭环**（先半闭环）
- ❌ **不要一上来就联邦学习**（先单厂做透）
- ❌ **不要让工艺师感觉"AI 在替我做决定"**（要"帮我做更好的决定"）
- ❌ **不要追求"+25% / -40%" 数字承诺**（先量化基线再说）

### 9.3 必做策略

- ✅ **新功能作为"可选插件"**（基础 / 增强 / 完全 APT 三档）
- ✅ **旧路径 LNN 直接预测保留**（永远 fallback）
- ✅ **A/B 测试基础设施**（不要凭感觉改）
- ✅ **每周可演示成果**（防止"做到一半发现走错路"）

## 十、验证方法

### 10.1 验证四阶段

| 阶段 | 验证目标 | 方法 | 通过标准 |
|------|---------|------|----------|
| 离线 | 算法正确性 | 历史数据回放 | 关键指标 ≥ 现有基线 |
| 灰度 | 用户体验 | 5-10 个内部测试用户 | 接受度 > 70% |
| 试点 | 业务价值 | 1 个工厂 3 个月 | ROI 可见 |
| 推广 | 大规模可用 | 多工厂部署 | SLA 达标 |

### 10.2 关键指标（用数据说话）

- 方案生成成功率
- 切削参数合规率
- 碰撞率
- 试切次数（首次合格率）
- 单件工时
- 工艺师规划耗时
- 用户采纳率
- 模型不确定性均值
- 数据回灌量 / 周
- 飞轮转速度（数据量 ↔ 模型质量相关系数）

### 10.3 试点对比实验
- **A 组**：现有系统（6-Agent + LNN）
- **B 组**：APT 融合系统
- **评估维度**：
  1. 方案可行性率
  2. 工艺规划耗时
  3. 首次试切合格率
  4. 工艺师返工率
  5. 知识复用率（推荐参数与历史相似案例的吻合度）

### 10.4 试点工件（避免"通孔"陷阱）
不要选"45 钢通孔"——太简单，无法证明价值。应选：
- 复杂型腔（含岛屿/清根/粗精分离）
- 多工序组合件（车+铣）
- 难加工材料（钛合金/高温合金）
- 工艺规则冲突场景（同一特征多解）

## 十四、最后的话

> 灵境制造要成为现象级，**不是靠一个算法突破**，而是靠"**真数据 + 真客户 + 真闭环**"的飞轮。
>
> APT（自适应工艺孪生）是这个飞轮的**主引擎**，
> L1 增强层让主引擎**更强大**，
> L2 并行优化让现有系统**不拖后腿**，
> L3 基础能力让主引擎**成为行业生态**。
>
> **四者缺一，飞轮转不动。**
>
> **敢不敢做是另一个问题，但能不能做，技术上是能的。**
