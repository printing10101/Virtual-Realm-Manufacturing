## 一、版本概述

V1.12.1 是 V1.12.0 暂存代码上线前的**安全加固与质量收口**补丁版本。本版本不引入新功能，仅围绕"**安全漏洞收敛、并发与资源安全、功能缺陷修复、代码规范统一**"四大主题，对 V1.12.0 暂存区中所有 Python 核心模块、认证链路、审计日志、输入校验器进行系统化修复。

本版本共修改 **7 个核心源文件 + 2 个测试文件**，新增/补强测试用例 **12 个**，代码净增 **约 240 行**，无破坏性 API 变更。

**V1.12.1 核心亮点**:

- 路径遍历漏洞彻底闭环：`validate_file_path` 引入根目录白名单，支持调用方扩展
- 幂等性存储内存泄漏修复：定时清理 + LRU 上限 + 线程锁
- 认证中间件并发竞态修复：check-and-set 操作加锁序列化
- Token Ban List 持久化文件符号链接攻击防护
- 审计日志 CSV 注入防护：导出电子表格公式注入拦截
- TokenBanList 初始化 `AttributeError` 修复
- 审计日志搜索性能修复：按需窗口扫描，避免 O(n) 全表
- JWT 密钥随机性校验增强 + 测试可重置入口
- 异常吞没修复：审计日志写入失败由静默改为可观测
- 测试覆盖：路径遍历、白名单、相对路径、类型检查、CSV 注入等场景

## 二、修复的安全漏洞

### 2.1 [CWE-22] 路径遍历漏洞（`validate_file_path`）

**风险等级**: 🔴 **高危**

**问题描述**: V1.12.0 中 `validate_file_path` 仅校验路径是否存在及是否为空字符串，未限制访问范围。攻击者可通过以下方式绕过：
- 传入 `../../../etc/passwd` 形式的相对路径访问白名单外敏感文件
- 传入绝对路径（如 `/etc/shadow`）读取系统文件
- 利用 `..\\..\\windows\\system32` 在 Windows 上绕过

**修复方案**:
- 引入**根目录白名单机制**，默认包含 `LNN_DATA_DIR` / `LNN_OUTPUT_DIR` / `LNN_UPLOAD_DIR` 三类目录
- 调用方可通过 `allowed_roots` 参数扩展白名单
- 解析前先 `expanduser().resolve()` 消除符号链接与 `..` 影响
- 白名单检查在 `must_exist` 校验之前执行，避免暴露文件存在性
- 错误信息统一为"文件路径不在允许的访问范围内"，不泄露具体路径

**修复点**:
- `python/app/core/input_validator.py`:
  - 重写 `_resolve_allowed_roots`：环境变量动态读取（避免 import-time 副作用），fallback 到 CWD 默认子目录
  - 新增 `_is_within_allowed_roots`：使用 `Path.relative_to` 严格检查包含关系
  - `validate_file_path` 增加 `allowed_roots: Optional[Sequence[str]]` 参数

**测试覆盖** (`python/tests/test_input_validator.py`):
- `test_path_traversal_rejected`：构造白名单外文件，验证拒绝
- `test_path_traversal_dotdot_rejected`：构造 `../../../etc/passwd` 形式
- `test_custom_allowed_roots`：通过 `allowed_roots` 扩展白名单
- `test_non_string_path`：传入非字符串（int/None）应被拒绝
- `test_relative_path_existing`：白名单内的相对路径可正常解析

### 2.2 [CWE-400] 幂等性存储内存泄漏（`IdempotencyStore`）

**风险等级**: 🟠 **中危**

**问题描述**: `IdempotencyStore._keys` 在低流量服务中长期累积，缺少清理与上限控制，存在内存泄漏隐患；同时在并发请求下 check-and-set 不是原子操作，可能导致幂等性语义失效。

**修复方案**:
- 新增 `max_age`（默认 3600s）与 `max_entries`（默认 10000）双约束
- 每次 `check_and_set` / `store` 时按 `cleanup_interval`（min(300, max_age//4)）触发现清理
- 新增 `_maybe_cleanup_locked` 内部方法：清理过期条目；超上限时按插入顺序裁剪到 90%
- 新增 `threading.Lock` 保护 `_keys` 字典，check-and-set 原子化

**修复点**: `python/app/core/middleware/unified_auth.py::IdempotencyStore`

**测试覆盖** (`python/tests/unit/test_unified_auth_middleware.py`):
- `TestIdempotencyStore::test_store_and_retrieve`：基本存取
- `TestIdempotencyStore::test_different_agent`：不同 agent 隔离
- `TestIdempotencyStore::test_cleanup_expired`：过期清理

### 2.3 [CWE-362] 幂等性并发竞态

**风险等级**: 🟠 **中危**

**问题描述**: `IdempotencyStore` 缺少锁保护，并发请求可能同时通过 check-and-set，导致幂等性失效、重复扣费/重复扣预算等业务问题。

**修复方案**:
- 引入 `self._lock = threading.Lock()`
- 所有 `_keys` 字典读写均在 `with self._lock:` 上下文内
- 清理与淘汰在锁内进行，避免清理过程中插入新条目导致不一致

**修复点**: `python/app/core/middleware/unified_auth.py::IdempotencyStore`

### 2.4 [CWE-59] Token Ban List 符号链接攻击

**风险等级**: 🟡 **低危**

**问题描述**: `TokenBanList` 持久化到 `.ban_list.json` 时，攻击者可在 Ban List 文件路径中预先创建符号链接，诱导服务写入攻击者控制的文件。

**修复方案**:
- 写入文件前检查父目录是否合法
- 使用 `os.path.realpath` 解析最终路径，确保目标文件位于预期目录
- 临时文件 + 原子 rename 模式防御 TOCTOU 攻击

**修复点**: `python/app/core/middleware/unified_auth.py::TokenBanList._save` / `_load`

### 2.5 [CWE-1236] 审计日志 CSV 注入

**风险等级**: 🟡 **低危**

**问题描述**: 审计日志导出 CSV 时，恶意写入者可注入以 `=`、`+`、`-`、`@`、Tab/换行符开头的字段；下游用 Excel/LibreOffice 打开时会触发公式执行，导致数据外泄或命令执行。

**修复方案**:
- `_csv_escape` 在危险起始字符前加单引号前缀
- 同时正确处理引号转义（双引号包裹 + 内部双引号转义）
- 起始字符集合：`=`、`+`、`-`、`@`、`\t`、`\n`、`\r`

**修复点**: `python/app/core/audit_log.py::_csv_escape`

### 2.6 [CWE-755] 异常吞没

**风险等级**: 🟡 **低危**

**问题描述**: 审计日志写入失败时原代码仅 `pass` 静默，运维侧无法察觉日志丢失，违反可观测性原则。

**修复方案**:
- 写入失败时记录到 `logger.warning` 包含具体异常类型与 message
- 失败不阻塞业务路径（不抛异常到调用方）
- 关键路径写入失败时在响应头加 `X-Audit-Write-Failed: true` 提示前端（可选）

**修复点**: `python/app/core/audit_log.py::AgentAuditLog` / `AuditLogger`

## 三、修复的功能缺陷

### 3.1 TokenBanList 初始化 `AttributeError`

**问题描述**: `TokenBanList.__init__` 未显式初始化 `_expiry` 字典，仅在 `_cleanup_expired` 方法内做变量注解。当 `_load()` 触发时若文件不存在或为空，会调用 `_cleanup_expired` 访问 `self._expiry`，抛出 `AttributeError`。

**修复方案**:
- `__init__` 内显式初始化 `self._expiry: dict[str, str] = {}`
- 添加注释说明 `_expiry` 与 `_banned` 的区别（过期 token 与永久 ban 的分离存储）

**修复点**: `python/app/core/security.py::TokenBanList.__init__`

### 3.2 审计日志搜索性能

**问题描述**: `AuditLogEntry.search_logs` 无视 `limit` 参数，无条件读取最近 10,000 条日志再在内存中过滤关键词。在百万级日志场景下，每次搜索都触发 O(n) 全表扫描，内存峰值不可控。

**修复方案**:
- 按 `limit * 5` 与下限 `500` 之间取最大值作为 `scan_window`
- `scan_window` 上限 10,000（与原 `get_logs` 默认一致）
- 收集到 `limit` 条结果后立即 break，不再继续扫描
- `keyword` 为空时直接返回空列表（不触发任何 IO）

**修复点**: `python/app/core/audit_log.py::AuditLogger.search_logs`

### 3.3 JWT 密钥随机性校验增强

**问题描述**: 原有 `_validate_and_get_secret` 在密钥长度不足时拒绝，但对全相同字符（如 `aaaa...`）的弱密钥不检测。

**修复方案**:
- 新增唯一字符集检测：唯一字符数 / 总长度 < 0.3 视为弱密钥
- 提升随机性要求：连续相同字符 > 8 视为弱密钥
- 新增 `_reset_secret_for_testing` 显式入口：仅供单元测试替换 SECRET_KEY，正常业务代码不应调用

**修复点**: `python/app/core/security.py`

### 7.2 部署注意事项

- **环境变量配置**: 部署到 V1.12.1 时必须正确设置 `LNN_DATA_DIR` / `LNN_OUTPUT_DIR` / `LNN_UPLOAD_DIR` 三个环境变量之一，否则 `validate_file_path` 将拒绝所有路径。fallback 行为为 CWD 下的 `data/output/uploads` 子目录。
- **Token Ban List 文件权限**: 升级前检查 `.ban_list.json` 所在目录权限，确保运行用户可读写。原子 rename 要求同分区。
- **CSV 注入防护**: 如果有外部脚本依赖原始字段首字符（`=` 等），需要相应更新解析逻辑；本版本仅在审计日志 CSV 导出中生效。

### 7.3 客户端适配

- **Python SDK 调用方**: 涉及文件路径的 API（数据集上传、模型导入导出、报告生成等）若传入绝对路径或非常规路径，需调用方在 `LNN_DATA_DIR` 之内，或使用 `validate_file_path(allowed_roots=[...])` 显式放行。
