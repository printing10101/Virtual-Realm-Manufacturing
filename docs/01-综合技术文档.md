## 一、项目概况

### 1.1 项目定位

**灵境制造** 是一款基于神经逻辑网络（LNN）的智能制造 AI 推理与训练桌面应用，采用 Tauri 2 + Vue 3 + Python FastAPI 架构，支持本地 LNN 模型推理和训练，以及可选的云端 LLM 调用。

### 1.2 核心功能

| 功能模块      | 描述                              |
| --------- | ------------------------------- |
| LNN 预测推理 | 基于神经逻辑网络（LNN）的切削参数智能预测 |
| LNN 模型训练 | 支持 CFC、LTC、HybridLNN 等模型的在线训练 |
| 模型注册管理 | LNN 模型注册、验证、版本管理、量化压缩 |
| Agent 系统 | 多智能体协作、状态管理、技能注册、治理审批 |
| 模板系统 | 模板模式引擎、A/B 测试、分支管理、进化算法、模板市场 |
| 工艺规划 | 2D/3D 特征识别（孔、槽、凸台、腔体）、工序排序、夹具推荐、刀具匹配 |
| NC 代码生成 | 多后处理器支持（FANUC、Siemens、Heidenhain） |
| 加工仿真 | 体素化切削、碰撞检测、刀路解析与可视化 |
| STEP 导入解析 | STEP 文件解析、缓存、几何特征提取 |
| DXF 图纸解析 | DXF 文件解析、特征提取、工艺路由 |
| RAG 知识库 | 文档检索、向量存储、知识问答 |
| 刀具磨损预测 | 基于 Uniwear 数据集的刀具磨损预测与校准 |
| 插件系统 | 插件安装、依赖管理、技能加载、插件市场 |
| 成本预算 | 成本跟踪、预算限制、能力门控 |
| 用户主权 | 用户数据控制、经验存储、模型校准 |
| SSE 实时推送 | Server-Sent Events 实时任务进度推送 |
| 3D 模型查看   | Three.js 渲染 STL/OBJ/GLTF 格式模型   |
| 本地 LLM 支持 | Ollama 本地推理，支持多种开源模型 |
| 监控与可观测性 | Prometheus 指标、环形日志、健康检查、诊断报告 |

### 1.3 隐私原则

**核心原则：数据不出本地设备**

1. **默认本地模式**: 所有 AI 推理默认使用本地 LNN 模型和 Ollama
2. **可选云端模式**: 用户显式配置，仅非敏感文本可走云端
3. **完全离线模式**: 关闭所有网络请求，降级为规则引擎
4. **本地存储**: 用户数据存储在本地目录，支持用户主权控制
5. **无遥测**: 不收集任何用户行为数据
6. **JWT 认证**: 可选的 JWT Token 认证机制
7. **统一认证中间件**: 合并 LNN + JWT + Agent 三重认证
8. **权限门控**: 基于权限的能力门控机制

// src/router/index.ts
const routes = [

### 6.5 SidecarManager 进程管理（核心模块）

**文件**: `src-tauri/src/sidecar_manager.rs`

SidecarManager 是 Rust 层最核心的模块，负责 Python FastAPI 进程的完整生命周期管理：

| 组件 | 职责 |
|------|------|
| `PortAllocator` | 动态端口分配（10000-60000 范围），通过 `TcpListener::bind` 检测端口可用性 |
| `StateFileManager` | 状态文件读写（JSON），支持原子写入（write → rename） |
| `HealthChecker` | 健康检查（HTTP `/health` 端点）和进程存活检测（跨平台） |
| `GracefulShutdownManager` | 优雅关闭（SIGTERM/`taskkill /T` → 等待超时 → 强制 kill/SIGKILL） |
| `SidecarManager` | 整合以上组件，提供 `recover_or_start()`, `start_fresh()`, `graceful_shutdown()` |

**状态文件结构** (`SidecarStateFile`):
```json
{
  "pid": 12345,
  "port": 8000,
  "token": "uuid-v4-string",
  "start_time": "2026-05-20T10:00:00Z",
  "version": "1.11.0",
  "status": "running"
}
```

**进程恢复策略**:
1. 检查状态文件是否存在
2. 验证 PID 是否存活
3. 如果存活，尝试连接并验证令牌
4. 如果连接失败或进程不存活，强制重启
5. 自动重连最多 3 次，使用指数退避

## 十一、技术难点解析

### 11.1 难点一：LNN 模型训练与推理平衡

**问题**: LNN 模型（CFC/LTC）基于 Neural ODE，训练和推理计算密集。

**解决方案**:

1. AMP（自动混合精度）加速推理
2. GPU 优先调度（自动检测 CUDA）
3. 模型注册和缓存避免重复加载
4. 后台训练任务不阻塞推理

### 11.2 难点二：三层通信延迟优化

**问题**: 前端 → Tauri → Python → LNN 链路过长，每层都有序列化开销。

**解决方案**:

1. 减少不必要的中间层转换
2. 使用异步操作减少阻塞等待
3. HTTP 代理模块支持请求批处理和连接复用

### 11.3 难点三：路径遍历安全

**问题**: 用户传入的文件路径可能导致越权访问系统文件。

**解决方案**:

```rust
fn sanitize_path(user_path: &str, base_dir: &Path) -> Result<PathBuf, String> {
    // 三重验证机制
    // 1. 禁止 ".." 路径遍历
    // 2. 自动创建父级目录
    // 3. 验证路径在应用目录内
}
```

### 11.4 难点四：Three.js 内存泄漏

**问题**: 组件卸载时未释放 WebGL 资源，导致内存持续增长。

**解决方案**:

```typescript
onUnmounted(() => {
  // 完整释放：geometry、material、renderer、context
})
```

### 11.5 难点五：跨平台进程管理

**问题**: Windows 和 Unix 系统的进程管理 API 不同。

**解决方案**:

```rust
fn is_process_alive(pid: u32) -> bool {
    #[cfg(windows)]
    { /* tasklist 命令 */ }
    #[cfg(unix)]
    { /* kill -0 信号 */ }
}
```

### 11.6 难点六：Uniwear 数据集处理

**问题**: PHM2010 等高频振动数据集体积大，加载和预处理耗时。

**解决方案**:

- 使用 pandas/numpy 高效处理
- 分批加载避免内存溢出
- 数据预处理管道化
- 数据集缓存（`dataset_cache.py`）

### 11.7 难点七：多层认证系统

**问题**: 需要同时支持 LNN Token、JWT Token 和 Agent Token 三种认证方式，且需要统一处理。

**解决方案**:

- 实现 `UnifiedAuthMiddleware` 合并三种认证逻辑
- 纯 ASGI 中间件，避免 BaseHTTPMiddleware 带来的性能开销
- 可配置开关（`auth_enabled`, `jwt_auth_enabled`, `agent_auth_enabled`）
- 权限门控基于角色和权限声明

### 11.8 难点八：Sidecar 进程弹性管理

**问题**: Python sidecar 进程可能因各种原因崩溃，需要自动恢复且不中断用户体验。

**解决方案**:

- `SidecarManager` 四组件架构（PortAllocator, StateFileManager, HealthChecker, GracefulShutdownManager）
- 状态文件持久化（原子写入：write → rename）
- Crash Recovery：自动检测进程存活并尝试重连
- 指数退避自动重连（最多 3 次）
- 优雅关闭（SIGTERM → 等待超时 → 强制 kill）
- 空闲超时自动关闭（1800 秒）

### 11.9 难点九：Agent 系统复杂性

**问题**: 多智能体协作需要目标链管理、技能注册、治理审批、成本跟踪等多个子系统协同。

**解决方案**:

- `AsyncTaskManager` 统一管理并发任务
- `GoalChainStore` 管理目标链持久化
- `BudgetEnforcer` 和 `CapabilityGating` 控制执行边界
- `ApprovalWorkflow` 实现多级审批
- `AuditLog` 记录所有操作
- SSE 实时推送 Agent 状态变更

### 11.10 难点十：模板系统进化

**问题**: 模板需要支持模式匹配、A/B 测试、分支管理、进化算法、市场发布等多个功能。

**解决方案**:

- `PatternEngine` 实现模板模式匹配
- `TemplateABTesting` 框架支持对比实验
- `TemplateBranching` 管理多版本分支
- `TemplateEvolution` 实现遗传算法优化
- `TemplateMarketplace` 提供模板发布和订阅
- `TemplateUpdateService` 管理版本更新
