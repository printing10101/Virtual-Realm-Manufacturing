## 一、项目概况

### 1.1 项目定位

**灵境制造** 是一款基于神经逻辑网络（LNN）的智能制造 AI 推理与训练桌面应用，采用 Tauri 2 + Vue 3 + Python FastAPI 架构，支持本地 LNN 模型推理和训练，以及可选的云端 LLM 调用。

### 1.2 核心功能

| 功能模块      | 描述                              |
| --------- | ------------------------------- |
| LNN 预测推理 | 基于神经逻辑网络（LNN）的切削参数智能预测 |
| LNN 模型训练 | 支持 CFC、LTC、HybridLNN 等模型的在线训练 |
| 模型注册管理 | LNN 模型注册、验证、版本管理 |
| 3D 模型查看   | Three.js 渲染 STL/OBJ/GLTF 格式模型   |
| 工作空间管理 | 项目工作区管理 |
| 本地 LLM 支持 | Ollama 本地推理，支持多种开源模型（通过配置支持） |
| 数据备份      | 设置与数据自动备份与恢复 |
| 监控与可观测性 | Prometheus + Grafana 集成监控 |

### 1.3 隐私原则

**核心原则：数据不出本地设备**

1. **默认本地模式**: 所有 AI 推理默认使用本地 LNN 模型和 Ollama
2. **可选云端模式**: 用户显式配置，仅非敏感文本可走云端
3. **完全离线模式**: 关闭所有网络请求，降级为规则引擎
4. **本地存储**: 用户数据存储在本地目录
5. **无遥测**: 不收集任何用户行为数据
6. **开发环境 CORS**: 开发环境使用通配符 CORS 策略（生产环境需收紧）

## 八、数据流程设计

### 8.1 LNN 推理流程

```
用户输入（切削参数/特征数据）
    │
    ├── 数据预处理（标准化、特征提取）
    │
    ├── 模型选择（CFC/LTC/HybridLNN）
    │   │
    │   ├── 从注册表获取模型
    │   ├── 加载模型权重
    │   └── 执行推理
    │
    ├── AMP 推理（如支持）
    │
    └── 后处理（置信度计算、结果格式化）
        │
        └── 返回预测结果
```

### 8.2 LNN 训练流程

```
准备数据集（CSV/HDF5）
    │
    ├── 数据加载和预处理
    │
    ├── 划分训练集/验证集（80/20）
    │
    ├── 创建 DataLoader
    │
    ├── 初始化 LNNTrainer
    │
    ├── 训练循环（多轮 epoch）
    │   ├── 前向传播
    │   ├── 损失计算（MSE）
    │   ├── 反向传播
    │   └── 优化器更新
    │
    └── 保存训练结果和指标
```

### 8.3 通信链路

```
前端 (Vue) 
    │ ← Tauri invoke() / HTTP 请求
    ↓
Rust (Tauri Core)
    │ ← HTTP 代理
    ↓
Python (FastAPI)
    │ ← HTTP 请求
    ↓
LNN 引擎 / Ollama (LLM)
```

**预估延迟**:

| 通信路径            | 延迟             | 说明             |
| --------------- | -------------- | -------------- |
| 前端 → Tauri      | ~1ms          | IPC 序列化开销      |
| Tauri → Python  | ~5-20ms       | HTTP 请求 + 反序列化 |
| Python → LNN   | ~1-50ms       | LNN 推理（视模型大小）  |
| **全链路**         | **~7-71ms** | 累积延迟           |

### 8.4 数据持久化策略

| 数据类型  | 存储位置                    | 存储方式               | 说明          |
| ----- | ----------------------- | ------------------ | ----------- |
| 应用设置  | JSON 文件                 | serde_json / json | Rust/Python 层 |

| 模型权重 | 本地文件系统                  | PyTorch .pt 文件    | 按模型名称命名   |

## 十一、技术难点解析

### 11.1 难点一：LNN 模型训练与推理平衡

**问题**: LNN 模型（CFC/LTC）基于 Neural ODE，训练和推理计算密集。

**解决方案**:

1. AMP（自动混合精度）加速推理
2. GPU 优先调度（自动检测 CUDA）
3. 模型注册和缓存避免重复加载
4. 后台训练任务不阻塞推理

### 11.2 难点二：三层通信延迟优化

**问题**: 前端 → Tauri → Python → LNN 链路过长，每层都有序列化开销。

**解决方案**:

1. 减少不必要的中间层转换
2. 使用异步操作减少阻塞等待
3. HTTP 代理模块支持请求批处理和连接复用

### 11.3 难点三：路径遍历安全

**问题**: 用户传入的文件路径可能导致越权访问系统文件。

**解决方案**:

```rust
fn sanitize_path(user_path: &str, base_dir: &Path) -> Result<PathBuf, String> {
    // 三重验证机制
    // 1. 禁止 ".." 路径遍历
    // 2. 自动创建父级目录
    // 3. 验证路径在应用目录内
}
```

### 11.4 难点四：Three.js 内存泄漏

**问题**: 组件卸载时未释放 WebGL 资源，导致内存持续增长。

**解决方案**:

```typescript
onUnmounted(() => {
  // 完整释放：geometry、material、renderer、context
})
```

### 11.5 难点五：跨平台进程管理

**问题**: Windows 和 Unix 系统的进程管理 API 不同。

**解决方案**:

```rust
fn is_process_alive(pid: u32) -> bool {
    #[cfg(windows)]
    { /* tasklist 命令 */ }
    #[cfg(unix)]
    { /* kill -0 信号 */ }
}
```

### 11.6 难点六：Uniwear 数据集处理

**问题**: PHM2010 等高频振动数据集体积大，加载和预处理耗时。

**解决方案**:

- 使用 pandas/numpy 高效处理
- 分批加载避免内存溢出
- 数据预处理管道化
