## 一、项目概述

### 1.1 产品定位

**灵境制造 (LingJing Manufacturing)** 是一款面向制造行业的 AI 驱动 3D 模型生成与工艺管理桌面应用。

- **核心卖点**: 数据不出本地设备，AI 全流程辅助（三视图 → 3D模型 → 工艺规划 → NC代码 → 仿真验证 → 经验沉淀）
- **目标平台**: Windows（首发），后续扩展 macOS/Linux
- **分发渠道**: 微软商店 + 官网直接下载
- **适用团队**: 2-5 人小团队

### 1.2 核心功能

| 功能模块      | 描述                              |
| --------- | ------------------------------- |
| 三视图生成 3D  | 上传三视图图片，AI 自动生成 3D CAD 模型       |
| 工艺规划      | 六 Agent 协同工作流，支持串行/并行模式，自动生成加工工艺路线        |
| NC 代码生成   | 根据工艺路线和切削参数生成 G 代码/M 代码         |
| RAG 知识库   | 基于 ChromaDB 的制造工艺向量知识库，支持 Bosch CNC 真实工业数据     |
| 3D 模型查看   | Three.js 渲染 STL/OBJ/GLTF 格式模型   |
| 本地 LLM 支持 | Ollama 本地推理，支持多种开源模型            |
| 云端 LLM 支持 | 可选 OpenAI/DeepSeek 等云端 API      |
| 智能模型路由    | 根据任务复杂度自动选择本地/云端模型（V2.0新增）      |
| 仿真验证      | 基于 Bosch CNC 真实数据的阈值校准与工艺验证（V1.3新增）          |
| 经验回放      | 历史工艺经验检索、沉淀与复用（V2.0新增）          |
| 场景管理      | 多工业场景配置支持（消费电子、机器人、硬件等）（V2.0新增） |
| 工艺追踪      | 完整工艺演进过程追踪与可视化（V2.0新增）          |
| 刀具磨损预测    | 基于历史数据的刀具磨损趋势预测（V2.0新增）         |
| 模型微调      | 工艺模型在线微调与持续学习（V2.0新增）           |
| 方案对比      | 多工艺方案横向对比分析（V2.0新增）             |
| 文档中心      | 自动生成工艺报告与技术文档（V2.0新增）           |
| 数据备份      | 设置与数据自动备份与恢复（V1.3新增）           |
| 批量请求      | API 请求批处理与合并优化（V1.3新增）          |

### 1.3 隐私设计原则

**核心原则：数据不出本地设备**

1. **默认本地模式**: 所有 AI 推理默认使用本地 Ollama
2. **可选云端模式**: 用户显式配置，仅非敏感文本可走云端
3. **完全离线模式**: 关闭所有网络请求，降级为规则引擎
4. **本地存储**: 用户数据存储在 `%APPDATA%/lingjing/`
5. **无遥测**: 不收集任何用户行为数据
6. **严格 CORS 策略**: 生产环境禁止使用通配符，明确指定允许来源

#### 4.4.3 工作流编排器

**文件**: `python/app/ai/workflow.py`, `python/app/ai/workflow_parallel.py`

```python
class WorkflowOrchestrator:
    def __init__(self, use_parallel: bool = True):
        # 支持串行/并行两种执行模式
        # 并行模式失败时自动降级到串行模式
        
    async def execute_workflow(self, user_input: str, progress_callback=None) -> dict:
        # 1. 尝试并行执行（如果启用）
        # 2. 失败时自动降级到串行执行
        # 3. 每个 Agent 执行前后更新进度
        # 4. 返回完整工艺规划结果
```

**执行模式**: 
- **并行模式**: 使用 `parallel_orchestrator` 加速执行
- **串行模式**: 顺序执行，每个 Agent 的输出作为下一个 Agent 的输入
- **自动降级**: 并行失败时自动切换到串行模式

## 六、数据流程设计

### 6.1 AI 模型路由策略

```
用户请求
    │
    ├── 输入验证（长度、材料、尺寸、公差）
    │
    ├── 复杂度评估（材料、刀具、约束、几何、历史）
    │   │
    │   ├── 评分 ≤ 3 → 本地 Ollama
    │   ├── 评分 4-7 → 本地 Ollama（失败降级到云端）
    │   └── 评分 ≥ 8 → 云端 API
    │
    ├── 敏感操作（CAD 文件分析、工艺参数生成）
    │   └── 强制本地 Ollama（即使配置了云端也不上传）
    │
    └── 离线模式
        └── 仅 Ollama（不可用时降级为规则引擎）
```

### 6.2 通信链路

```
前端 (Vue) 
    │ ← Tauri invoke() / HTTP 请求
    ↓
Rust (Tauri Core)
    │ ← HTTP 代理
    ↓
Python (FastAPI)
    │ ← HTTP 请求
    ↓
Ollama / 云端 API (LLM)
```

**预估延迟**:

| 通信路径            | 延迟             | 说明             |
| --------------- | -------------- | -------------- |
| 前端 → Tauri      | \~1ms          | IPC 序列化开销      |
| Tauri → Python  | \~5-20ms       | HTTP 请求 + 反序列化 |
| Python → Ollama | \~50-500ms     | LLM 推理（视模型大小）  |
| **全链路**         | **\~56-521ms** | 累积延迟           |

### 6.3 工作流数据流

```
用户输入
    ↓
[输入验证] → 长度、材料、尺寸、公差检查
    ↓
UnderstandingAgent → 提取参数 {material, part_type, dimensions, ...}
    ↓
PlanningAgent → 生成工艺路线 [{step, operation, machine, description}, ...]
    ↓
ParameterAgent → 计算切削参数 [{step, v, f, ap, n}, ...]
    ↓
NCAgent → 生成 NC 代码 (G代码/M代码)
    ↓
VerificationAgent → 验证结果 {is_valid, issues[], summary}
    ↓
RepairAgent → 优化建议 [suggestions...]
    ↓
返回完整工艺规划结果
```

**并行模式**: PlanningAgent 和 ParameterAgent 可并行执行，加速工作流。

### 6.4 验证校准数据流（V1.3 新增）

```
Bosch CNC 数据集
    ↓
[数据加载] → HDF5 文件解析 → 振动信号提取
    ↓
[特征工程] → RMS 值、频率偏移、统计特征
    ↓
[阈值校准] → 计算警告阈值(k=2σ) 和 临界阈值(k=3σ)
    ↓
[规则比较] → 校准值 vs 理论值
    ↓
[用户确认] → 是否应用校准规则
    ↓
[应用规则] → 更新验证引擎规则集
```

### 7.3 Agent 执行模式

每个 Agent 的实现遵循统一接口：

```python
class BaseAgent(ABC):
    @abstractmethod
    async def execute(self, context: AgentContext) -> AgentContext:
        pass
```

**关键设计**:

1. **RAG 增强**: 每个 Agent 执行前先从知识库检索相关知识
2. **JSON 解析**: 使用 LLM 返回 JSON 格式结果，支持 \`\`\`json 代码块提取
3. **降级策略**: JSON 解析失败时使用默认值确保流程继续
4. **错误捕获**: 每个 Agent 内部捕获异常，更新 stage\_status
5. **模型路由**: 通过 ModelRouter 智能选择本地/云端模型
6. **输入验证**: 集成 InputValidationMiddleware，验证用户输入
7. **Bosch 优先**: 检索结果优先使用 Bosch CNC 真实工业数据

## 十一、技术难点解析

### 11.1 难点一：三层通信延迟优化

**问题**: 前端 → Tauri → Python → Ollama 链路过长，每层都有序列化开销。

**解决方案**:

1. 减少不必要的中间层转换
2. 使用异步操作减少阻塞等待
3. 引入 SSE 推送减少前端轮询
4. HTTP 代理模块（V1.3）支持请求批处理和连接复用
5. 未来可考虑 gRPC 替代 HTTP 通信

### 11.2 难点二：路径遍历安全

**问题**: 用户传入的文件路径可能导致越权访问系统文件。

**解决方案**:

```rust
fn sanitize_path(user_path: &str, base_dir: &Path) -> Result<PathBuf, String> {
    // 三重验证机制
    // 1. 禁止 ".." 路径遍历
    // 2. 自动创建父级目录
    // 3. 验证路径在应用目录内
}
```

### 11.3 难点三：Three.js 内存泄漏

**问题**: 组件卸载时未释放 WebGL 资源，导致内存持续增长。

**解决方案**:

```typescript
onUnmounted(() => {
  // 完整释放：geometry、material、renderer、context
})
```

### 11.4 难点四：Agent 工作流降级

**问题**: LLM 推理可能失败或返回无效 JSON。

**解决方案**:

- 每个 Agent 捕获异常
- JSON 解析失败时使用预设默认值
- 工作流编排器捕获整体异常，返回已完成阶段结果
- ModelRouter 提供本地到云端的降级路径
- 并行工作流失败时自动降级到串行模式

### 11.5 难点五：CORS 安全配置

**问题**: 通配符 CORS 配置可能导致跨站攻击。

**解决方案**:

- 所有环境禁止使用 `"*"` 通配符
- 根据环境动态配置允许的来源列表
- 启动时验证 CORS 配置，不合规则拒绝启动
- 生产环境检测到宽松配置时记录高级别警告

### 11.6 难点六：跨平台进程管理

**问题**: Windows 和 Unix 系统的进程管理 API 不同。

**解决方案**:

```rust
fn is_process_alive(pid: u32) -> bool {
    #[cfg(windows)]
    { /* tasklist 命令 */ }
    #[cfg(unix)]
    { /* kill -0 信号 */ }
}
```

### 11.7 难点七：Bosch CNC 数据集集成（V1.3 新增）

**问题**: HDF5 格式数据集解析、特征提取、阈值计算。

**解决方案**:

- 使用 `h5py` 库读取 HDF5 文件
- 提取振动信号的 RMS 值、频率特征
- 统计各工序/机器的阈值分布
- 计算警告阈值和临界阈值（k=2σ, k=3σ）
- 提供校准规则比较和应用机制

### 11.8 难点八：请求批处理优化（V1.3 新增）

**问题**: 大量并发 API 请求导致网络开销增加。

**解决方案**:

- Rust 层提供 HTTP 代理模块
- 前端实现请求批处理基类和执行器
- 合并相似请求，减少重复调用
- 支持连接复用和错误重试
