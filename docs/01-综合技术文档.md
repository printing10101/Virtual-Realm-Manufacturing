## 一、项目概述

### 1.1 产品定位

**灵境制造 (LingJing Manufacturing)** 是一款面向制造行业的 AI 驱动 3D 模型生成与工艺管理桌面应用。

- **核心卖点**: 数据不出本地设备，AI 全流程辅助（三视图 → 3D模型 → 工艺规划 → NC代码）
- **目标平台**: Windows（首发），后续扩展 macOS/Linux
- **分发渠道**: 微软商店 + 官网直接下载
- **适用团队**: 2-5 人小团队

### 1.2 核心功能

| 功能模块 | 描述 |
|---------|------|
| 三视图生成 3D | 上传三视图图片，AI 自动生成 3D CAD 模型 |
| 工艺规划 | 六 Agent 协同工作流，自动生成加工工艺路线 |
| NC 代码生成 | 根据工艺路线和切削参数生成 G 代码/M 代码 |
| RAG 知识库 | 基于 ChromaDB 的制造工艺向量知识库 |
| 3D 模型查看 | Three.js 渲染 STL/OBJ/GLTF 格式模型 |
| 本地 LLM 支持 | Ollama 本地推理，支持多种开源模型 |
| 云端 LLM 支持 | 可选 OpenAI/DeepSeek 等云端 API |

### 1.3 隐私设计原则

**核心原则：数据不出本地设备**

1. **默认本地模式**: 所有 AI 推理默认使用本地 Ollama
2. **可选云端模式**: 用户显式配置，仅非敏感文本可走云端
3. **完全离线模式**: 关闭所有网络请求，降级为规则引擎
4. **本地存储**: 用户数据存储在 `%APPDATA%/lingjing/`
5. **无遥测**: 不收集任何用户行为数据

```typescript
  // 1. 停止动画循环
  if (animationId) cancelAnimationFrame(animationId)
  
  // 2. 释放模型资源
  if (modelMesh) {
    modelMesh.traverse((child) => {
      if (child instanceof THREE.Mesh) {
        child.geometry?.dispose()
        if (Array.isArray(child.material)) {
          child.material.forEach(m => m.dispose())
        } else {
          child.material?.dispose()
        }
      }
    })
    scene.remove(modelMesh)
    modelMesh = null
  }
  
  // 3. 释放渲染器
  if (renderer) {
    renderer.dispose()
    renderer.forceContextLoss()
    if (renderer.domElement.parentNode) {
      renderer.domElement.parentNode.removeChild(renderer.domElement)
    }
  }
  
  // 4. 移除事件监听
  window.removeEventListener('resize', onWindowResize)
})
```

#### 4.3.1 文件系统操作（安全版）

**文件**: `src-tauri/src/commands/file.rs`

采用路径白名单机制，防止路径遍历攻击：

```rust
fn sanitize_path(user_path: &str, base_dir: &Path) -> Result<PathBuf, String> {
    let full_path = base_dir.join(user_path);
    
    // 1. 检测路径遍历标记
    let path_str = full_path.to_string_lossy();
    if path_str.contains("..") {
        return Err("Access denied: relative path traversal not allowed".to_string());
    }
    
    // 2. 自动创建父级目录
    let parent = full_path.parent().unwrap_or(base_dir);
    if !parent.exists() {
        fs::create_dir_all(parent)?;
    }
    
    // 3. 验证最终路径在应用目录内
    if !full_path.starts_with(base_dir) {
        return Err("Access denied: path outside app directory".to_string());
    }
    
    Ok(full_path)
}

#[tauri::command]
pub fn save_file(file_path: String, content: String, app_handle: tauri::AppHandle) -> Result<(), String> {
    let base_dir = get_app_base_dir(&app_handle)?;
    let safe_path = sanitize_path(&file_path, &base_dir)?;
    fs::write(&safe_path, &content)?;
    Ok(())
}
```

```python
class WorkflowOrchestrator:
    def __init__(self):
        self.agents = {
            "understanding": UnderstandingAgent(),
            "planning": PlanningAgent(),
            "parameter": ParameterAgent(),
            "nc_generation": NCAgent(),
            "verification": VerificationAgent(),
            "repair": RepairAgent()
        }
        self.workflow_stages = [
            "understanding", "planning", "parameter",
            "nc_generation", "verification", "repair"
        ]

    async def execute_workflow(self, user_input: str, progress_callback=None) -> dict:
        context = AgentContext(user_input=user_input)
        for stage_name in self.workflow_stages:
            agent = self.agents[stage_name]
            # 进度回调
            if progress_callback:
                progress_callback({...})
            # 执行 Agent
            context = await agent.execute(context)
        return {完整的工艺规划结果}
```

**执行模式**: 顺序执行，每个 Agent 的输出作为下一个 Agent 的输入。

## 六、数据流程设计

### 6.1 AI 模型路由策略

```
用户请求
    │
    ├── 敏感操作（CAD 文件分析、工艺参数生成）
    │   └── 强制本地 Ollama（即使配置了云端也不上传）
    │
    ├── 一般操作（文本理解、文档查询）
    │   ├── 用户选择"本地" → Ollama
    │   └── 用户选择"云端" → 云端 API（需确认）
    │
    └── 离线模式
        └── 仅 Ollama（不可用时降级为规则引擎）
```

### 6.2 通信链路

```
前端 (Vue) 
    │ ← Tauri invoke()
    ↓
Rust (Tauri Core)
    │ ← HTTP 请求
    ↓
Python (FastAPI)
    │ ← HTTP 请求
    ↓
Ollama / 云端 API (LLM)
```

**预估延迟**:

| 通信路径 | 延迟 | 说明 |
|----------|------|------|
| 前端 → Tauri | ~1ms | IPC 序列化开销 |
| Tauri → Python | ~5-20ms | HTTP 请求 + 反序列化 |
| Python → Ollama | ~50-500ms | LLM 推理（视模型大小） |
| **全链路** | **~56-521ms** | 累积延迟 |

### 6.3 工作流数据流

```
用户输入
    ↓
UnderstandingAgent → 提取参数 {material, part_type, dimensions, ...}
    ↓
PlanningAgent → 生成工艺路线 [{step, operation, machine, description}, ...]
    ↓
ParameterAgent → 计算切削参数 [{step, v, f, ap, n}, ...]
    ↓
NCAgent → 生成 NC 代码 (G代码/M代码)
    ↓
VerificationAgent → 验证结果 {is_valid, issues[], summary}
    ↓
RepairAgent → 优化建议 [suggestions...]
    ↓
返回完整工艺规划结果
```

### 6.4 数据持久化策略

| 数据类型 | 存储位置 | 存储方式 | 说明 |
|---------|---------|---------|------|
| 应用设置 | SQLite (lingjing.db) | key-value 表 | 自动从 JSON 迁移 |
| 项目元数据 | SQLite (lingjing.db) | projects 表 | 支持事务、索引 |
| API Key | Windows Credential Manager | 系统密钥链 | 高安全级别 |
| 知识库向量 | ChromaDB (./chroma_db) | 向量数据库 | 语义检索 |
| 生成模型 | 本地文件系统 | STL/OBJ/GLTF | 按 UUID 命名 |

```rust
fn main() {
  let app_state = AppState::new();

    .manage(app_state)
    .setup(|app| {
      // 1. 创建应用数据目录

      std::fs::create_dir_all(&app_data_dir)?;

    })

      commands::get_app_data_dir,

      // ... 其他命令

}
```

## 十一、技术难点解析

### 11.1 难点一：三层通信延迟优化

**问题**: 前端 → Tauri → Python → Ollama 链路过长，每层都有序列化开销。

**解决方案**:
1. 减少不必要的中间层转换
2. 使用异步操作减少阻塞等待
3. 未来可考虑 gRPC 替代 HTTP 通信

### 11.2 难点二：路径遍历安全

**问题**: 用户传入的文件路径可能导致越权访问系统文件。

**解决方案**:
```rust
fn sanitize_path(user_path: &str, base_dir: &Path) -> Result<PathBuf, String> {
    // 三重验证机制
    // 1. 禁止 ".." 路径遍历
    // 2. 自动创建父级目录
    // 3. 验证路径在应用目录内
}
```

### 11.3 难点三：Three.js 内存泄漏

**问题**: 组件卸载时未释放 WebGL 资源，导致内存持续增长。

**解决方案**:
```typescript
onUnmounted(() => {
  // 完整释放：geometry、material、renderer、context
})
```

### 11.4 难点四：Agent 工作流降级

**问题**: LLM 推理可能失败或返回无效 JSON。

**解决方案**:
- 每个 Agent 捕获异常
- JSON 解析失败时使用预设默认值
- 工作流编排器捕获整体异常，返回已完成阶段结果

### 11.5 难点五：数据存储迁移

**问题**: 从 JSON 文件迁移到 SQLite，需要保证数据完整性。

**解决方案**:
```rust
pub fn migrate_from_json(db: &Database) {
    // 1. 读取 JSON 文件
    // 2. 写入 SQLite
    // 3. 成功后重命名为 .json.bak
    // 4. 失败时保留原 JSON 文件
}
```

### 11.6 难点六：跨平台进程管理

**问题**: Windows 和 Unix 系统的进程管理 API 不同。

**解决方案**:
```rust
fn is_process_alive(pid: u32) -> bool {
    #[cfg(windows)]
```
