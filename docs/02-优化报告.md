## 一、项目概况

### 1.1 项目定位

**灵境制造** 是一款基于神经逻辑网络（LNN）的智能制造 AI 推理与训练桌面应用，采用 Tauri 2 + Vue 3 + Rust + Python FastAPI 四层架构，核心 AI 引擎为 LNN（CFC、LTC、HybridLNN 模型），支持 Uniwear 刀具磨损数据集处理和 Prometheus + Grafana 可观测性集成。

### 1.2 代码规模统计

| 层级 | 文件数 | 代码行数（约） | 语言 |
|------|--------|--------------|------|
| 前端（Vue） | 10+ | ~1200 | TypeScript/Vue |
| Rust 后端 | 12+ | ~1000 | Rust |
| Python 后端（LNN） | 30+ | ~3500 | Python |
| 配置文件 | 10 | ~400 | JSON/TOML/YAML |
| **合计** | **60+** | **~6100** | **多语言** |

### 1.3 架构概览

```
┌─────────────────────────────────────────────────┐
│  Vue 3 前端 (WebView2)                          │
│  ├── Three.js 3D 渲染                           │
│  ├── Element Plus UI                            │
│  └── Pinia 状态管理                             │
├─────────────────────────────────────────────────┤
│  Rust 后端 (Tauri Core) - 扁平模块 (V2.0.0)      │
│  ├── Sidecar 进程管理 (7 个 Tauri 命令)         │
│  └── 应用信息查询 (版本/端口)                    │
├─────────────────────────────────────────────────┤
│  Python FastAPI (Sidecar) - 27 个 include_router 路由注册  │
│  ├── LNN 引擎 (CFC/LTC/Hybrid/Parameter)            │
│  ├── 模型注册系统（LNNModelRegistry）                  │
│  ├── LNN 训练器（PyTorch + AMP + 量化）              │

│  ├── 工艺规划 / 加工仿真 / 规则引擎 / 模板系统        │
```

> V2.0.0 重要变更：Rust 后端从"文件系统 + 进程管理 + 持久化 + HTTP 代理"四方职责收敛为"Sidecar 进程管控 + 应用信息查询"两点职责；HTTP 代理已移除，文件操作、设置/项目管理已下沉至 Python FastAPI 端。

## 三、性能瓶颈分析

### 3.1 通信链路瓶颈

#### 3.1.1 问题描述

用户操作需要经过三层传递：前端 → Tauri/Rust → Python/FastAPI → LNN 引擎，每层都涉及 HTTP 请求和 JSON 序列化/反序列化。

#### 3.1.2 延迟分析

```
前端 → Tauri IPC:     ~1ms    (JSON 序列化/反序列化)
Tauri → Python HTTP:  ~5-20ms (HTTP 请求 + 网络栈 + 反序列化)
Python → LNN 推理:    ~1-50ms (LNN 前向传播，视模型大小)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
全链路累计:            ~7-71ms
```

#### 3.1.3 根因分析

1. **序列化开销**: JSON 序列化/反序列化在各层重复执行
2. **HTTP 协议开销**: Tauri → Python 使用 HTTP 协议，存在 TCP 握手、请求头传输等开销
3. **同步等待**: 前端调用 Tauri 命令为同步等待模式

#### 3.1.4 影响范围

- LNN 预测推理：用户感知轻微延迟
- LNN 模型训练：训练启动和状态轮询有累积延迟
- 文件操作：相对影响较小（~20ms）

### 3.2 LNN 推理瓶颈

#### 3.2.1 已优化项

| 优化项 | 状态 | 说明 |
|--------|------|------|
| AMP 推理 | ✅ 已完成 | 自动混合精度加速推理 |
| 自动设备选择 | ✅ 已完成 | 自动检测 GPU/CPU |
| 模型注册缓存 | ✅ 已完成 | 避免重复加载模型 |

#### 3.2.2 仍存瓶颈

| 问题 | 影响 | 严重程度 |
|------|------|---------|
| 模型首次加载慢 | 冷启动延迟高 | 高 |
| 无模型权重缓存 | 每次启动需重新加载 | 中 |
| 批量推理未优化 | 多输入推理效率低 | 中 |
| 无模型量化 | 模型体积大，内存占用高 | 低 |

### 3.3 LNN 训练瓶颈

#### 3.3.1 数据集加载

Uniwear 刀具磨损数据集（PHM2010 等）为高频振动数据，使用 HDF5 格式，加载和预处理耗时：

```python
# 每个训练任务都需要
dataset = load_uniwear_data(path)  # HDF5 解析
features = extract_features(dataset)  # 特征工程
train_loader = DataLoader(dataset, batch_size=32)
```

- HDF5 文件解析：~500ms-2s（视文件大）
- 特征提取：~1-3s
- DataLoader 创建：~200ms

#### 3.3.2 Neural ODE 计算

CFC 和 LTC 模型基于 Neural ODE，训练时需要 ODE 求解器：

```
Epoch 训练时间:
CFC (small):  ~2-5 秒/epoch
LTC (small):  ~3-8 秒/epoch
HybridLNN:    ~5-15 秒/epoch
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
50 epochs:    ~100-750 秒 (1.5-12.5 分钟)
```

#### 3.3.3 后台训练任务

```python
@app.post("/api/v1/lnn/train")
async def train_lnn(request: TrainRequest):
    task = asyncio.create_task(train_background(request))
    # 后台执行，不阻塞主进程
```

- 训练任务为异步后台执行
- 前端需要轮询任务状态
- 无 SSE 推送，轮询频率影响性能

### 3.4 数据存储瓶颈

#### 3.4.1 JSON 文件存储（V1.x 历史）

```rust
// V1.x 历史实现，V2.0.0 起已下沉至 Python 侧
pub fn save_settings(settings: &AppSettings) -> Result<(), String> {
    let json = serde_json::to_string_pretty(settings)?;
    std::fs::write(settings_path, json)?;
}
```

> V2.0.0 起：Rust 侧不再持有设置/项目元数据的存储逻辑，全部由 Python FastAPI 侧的 `core/state_persistence.py` + `core/repository/json_repository.py` 负责，存放在应用数据目录下的 `data/` 目录。

#### 3.4.2 V2.0.0 当前实现

- 设置和项目元数据使用 JSON 文件存储（Python 侧 `core/repository/json_repository.py`）
- 无索引，查询效率随数据量增长下降
- 无事务支持，并发写入可能冲突
- 重型业务数据已迁移到 SQLite（`database/` + `core/repository/`）

### 3.5 Three.js 渲染瓶颈

| 问题 | 影响 | 严重程度 |
|------|------|---------|
| 无模型 LOD（细节层次） | 大模型渲染帧率下降 | 高 |
| 无模型压缩加载 | 加载时间较长 | 中 |
| 场景灯光未优化 | 多光源下渲染性能下降 | 低 |

## 六、优化方案

### 6.1 通信链路优化

#### 方案 1：使用 Tauri Events 替代 HTTP（推荐）

**目标**: 减少 Tauri → Python 的 HTTP 开销

```rust
// 前端通过 Tauri Events 订阅 Python 响应
listen('python-response', (event) => {
  // 直接接收数据，无 HTTP 开销
})

// Python 通过 Tauri emit 发送事件
app.emit_all("python-response", data)?;
```

**预期效果**: 延迟降低 ~5-10ms

#### 方案 2：批处理请求

**目标**: 减少多次小请求的累积开销

```typescript
// 将多个设置项合并为一次请求
await saveSettingsBatch({
  theme: 'dark',
  language: 'zh-CN',
  llm_mode: 'local'
})
```

**预期效果**: 减少 30-50% 的请求次数

#### 方案 3：gRPC 替代 HTTP（长期）

**目标**: 使用 Protocol Buffers 替代 JSON，减少序列化开销

| 对比项 | HTTP+JSON | gRPC+Protobuf |
|--------|-----------|---------------|
| 序列化大小 | 100% | ~30-50% |
| 延迟 | 基准 | -20-30% |
| 实现复杂度 | 低 | 高 |

**预期效果**: 延迟降低 ~20-30%，包体积减少 50-70%

### 6.2 LNN 推理优化

#### 方案 1：模型权重缓存

**目标**: 启动时预加载常用模型，避免冷启动延迟

```python
class ModelCache:
    def __init__(self):
        self.cache = {}  # model_name -> (model, timestamp)
    
    def get(self, model_name: str):
        if model_name in self.cache:
            return self.cache[model_name][0]
        # 否则加载模型
```

**预期效果**: 冷启动延迟减少 80-90%

#### 方案 2：模型量化（INT8/FP16）

**目标**: 减小模型体积，加速推理

```python
import torch
model = torch.load('model.pt')
model = torch.quantization.quantize_dynamic(
    model, {torch.nn.Linear}, dtype=torch.qint8
)
```

**预期效果**: 模型体积减少 50%，推理速度提升 20-40%

#### 方案 3：批量推理优化

**目标**: 多个输入合并为一次推理

```python
class BatchPredictor:
    def predict_batch(self, inputs: list) -> list:
        # 合并为 batch tensor
        batch_tensor = torch.stack(inputs)
        # 一次前向传播
        return self.model(batch_tensor)
```

**预期效果**: 多输入推理吞吐量提升 2-3x

### 6.3 LNN 训练优化

#### 方案 1：GPU 加速训练

**目标**: 使用 CUDA 加速 Neural ODE 计算

```python
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = model.to(device)
train_loader = DataLoader(dataset, batch_size=64, pin_memory=True)
```

**预期效果**: 训练时间减少 60-80%

#### 方案 2：数据集缓存

**目标**: 避免重复 HDF5 解析和特征提取

```python
class DatasetCache:
    def __init__(self):
        self.cache = {}  # file_hash -> (features, labels)
    
    def load(self, file_path):
        cache_key = hashlib.md5(file_path.encode()).hexdigest()
        if cache_key in self.cache:
            return self.cache[cache_key]
        # 否则解析 HDF5 并缓存
```

**预期效果**: 数据集加载时间减少 70-80%

#### 方案 3：异步训练状态推送

**目标**: 使用 SSE 替代轮询

```python
@app.get("/api/v1/lnn/train/{task_id}/stream")
async def train_stream(task_id: str):
    async def event_generator():
        while not task.done():
            yield f"data: {task.get_progress()}\n\n"
            await asyncio.sleep(0.5)
    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

**预期效果**: 减少轮询开销，实时性提升
