## 一、版本概述

V1.7.1 版本主要聚焦于前端代码质量优化、国际化(i18n)体系完善以及构建配置升级。本次更新将硬编码的中文文本全面迁移至 i18n 国际化系统，简化了 Vite 代码分割策略，并优化了测试配置，为后续多语言支持和持续集成奠定更坚实的基础。

## 二、主要功能变更说明

### 2.1 国际化(i18n)体系完善

#### 2.1.1 Settings 页面国际化迁移

**变更文件**: `src/views/Settings.vue`

将所有 Agent Token 管理、模块名称、决策名称、状态名称的硬编码中文文本迁移至 i18n 系统：

- **模块名称**: `lnn_predict`, `lnn_train`, `process_optimize`, `tool_wear_analyze`, `cad_generate`
- **决策名称**: `accept`, `modify`, `reject`, `auto_executed`
- **状态名称**: `success`, `failed`, `cancelled`, `pending`（迁移至 `common` 命名空间）
- **权限范围**: `R`（读取）, `W`（写入）, `B`（训练）, `N`（通知）, `C`（管理）, `T`（执行）
- **操作提示**: Token 创建成功提示、撤销确认、紧急停止确认、复制成功/失败提示

**技术实现**: 采用动态 key 映射（如 `settings.getScopeName_${scope}`），提升多语言扩展的灵活性。

#### 2.1.2 Workspace 页面国际化支持

**变更文件**: `src/views/Workspace.vue`

- 引入 `setLocale` 和 `SupportedLocale` 类型，支持运行时语言切换
- 移除直接导入的 `ElMessage`, `ElMessageBox`（由 i18n 系统统一管理）

#### 2.1.3 消息提示优化

**变更文件**: `src/views/TaskBoard.vue`, `src/views/TaskHistory.vue`

- 移除未使用的 `ElMessage`, `ElMessageBox` 导入，减少冗余依赖引用

---

### 2.2 Vite 构建配置升级

#### 2.2.1 代码分割策略简化

**变更文件**: `vite.config.ts`

**变更前**: 使用函数式 `manualChunks` 策略，按模块类型动态分块（three-vendor, echarts-vendor, element-plus-vendor, framework-vendor, vendor, view-xxx, components），逻辑复杂且维护成本高。

**变更后**: 采用静态声明式 `manualChunks` 策略，仅保留三个核心 chunk：
- `framework-vendor`: vue, vue-router, pinia
- `element-plus-icons`: @element-plus/icons-vue
- `element-plus-locale`: element-plus 中英文语言包

**优势**:
- 大幅简化构建配置逻辑，提升可读性
- 减少不必要的细粒度分块，降低 HTTP 请求数量
- 静态分块策略更稳定，避免动态分析的运行时开销

#### 2.2.2 Element Plus 按需导入优化

**变更文件**: `vite.config.ts`

- AutoImport 和 Components 插件的 `ElementPlusResolver` 统一添加 `{ importStyle: false }` 配置
- 配合 CSS 按需引入策略，避免样式重复加载
- 新增 `dts` 类型声明文件输出配置：
  - `src/auto-imports.d.ts`：自动导入 API 类型声明
  - `src/components.d.ts`：组件类型声明

---

### 2.3 测试配置优化

**变更文件**: `vitest.config.ts`

- 新增 `include: ['src/**/*.{test,spec}.{ts,js}']` 配置，明确测试文件匹配规则
- 避免将非测试文件误识别为测试用例，提升测试运行准确性

## 三、重要修复内容

### 3.1 样式导入冲突修复

**问题**: Element Plus 组件在 AutoImport/Components 自动导入时，可能因样式重复引入导致样式冲突或体积膨胀。

**修复**: 统一设置 `ElementPlusResolver({ importStyle: false })`，禁用自动样式导入，配合全局 CSS 按需引入策略，确保样式加载的一致性。

### 3.2 类型声明缺失修复

**问题**: 自动导入的 API（如 `ref`, `computed`, `onMounted`）和全局组件缺少 TypeScript 类型声明，导致 IDE 智能提示不完整。

**修复**: 在 AutoImport 和 Components 插件中配置 `dts` 输出路径，自动生成 `src/auto-imports.d.ts` 和 `src/components.d.ts` 类型声明文件。

### 3.3 测试文件匹配范围修复

**问题**: 未明确指定测试文件匹配规则时，Vitest 可能扫描到非测试文件，导致测试运行失败或误报。

**修复**: 添加 `include` 配置，限定测试文件仅匹配 `src/**/*.{test,spec}.{ts,js}` 格式。
