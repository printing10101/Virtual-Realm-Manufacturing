## 一、版本概述

V1.9.0 版本聚焦于制造流程的深度闭环能力建设，围绕**STEP文件导入解析**、**工艺规则可视化编辑**、**刀具路径交互式编辑**三大工作流展开。同时引入了**项目管理子系统**，实现从文件创建到保存下载的完整生命周期管理。前端UI进行了大规模重构，新增规则编辑器、刀具路径编辑器两个核心视图，并集成仿真控制面板、碰撞告警等交互组件。代码质量方面完成了多处关键Bug修复与架构优化。

**V1.9.0核心亮点**:
- 完整STEP文件导入管线（解析 → 转换 → 缓存 → 多精度导出）
- 工艺规则可视化编辑器，支持分组管理、条件编辑、导入导出，并与LNN推理引擎深度集成
- 交互式刀具路径编辑器，支持G代码解析、可视化渲染、段删除、进给率修改、命令历史撤销/重做
- 项目管理系统，支持新建/打开/保存/另存为/下载及修改状态追踪
- 仿真系统增强：体素切割引擎、前端3D仿真查看器、碰撞告警模态框
- Agent管线阶段状态枚举化，ManufacturingError异常处理器完善

## 三、Bug修复

### 3.1 engine.py 重复导入re模块

**问题**: `import re` 在 `_apply_rule_results()` 函数体内局部导入，每次调用该函数时都会重复执行import语句，造成不必要的运行时开销。

**修复**: 将 `import re` 移至文件顶部导入区（第10行），移除函数体内的局部导入。

**影响范围**: `python/app/ai/lnn/engine.py` 第10行、第644行

### 3.2 rule_db.py 中 result 为 None 时存储空字典导致解析错误

**问题**: 当 `rule.result` 为 `None` 时，`create_rule` 和 `update_rule` 两个方法均存储了 `json.dumps({})`（空字典），读取时 `json.loads('{}')` 得到空字典，然后 `RuleResult(**{})` 构造对象时因缺少必填字段 `parameter`、`operator`、`value` 引发 TypeError。

**修复**: 两处均改为 `json.dumps(None)`（JSON null），读取端 `RuleResult(**result) if result else None` 可正确处理 `None` 值。

**影响范围**: `python/app/database/rule_db.py` 第287行（create_rule）、第318行（update_rule）

### 3.3 LNN预测维度匹配修复

**问题**: 当预处理器已拟合（`is_fitted`）时，模型预测输出维度与预处理器 `mean_` 维度不匹配，导致 `inverse_transform` 失败。

**修复**: 在 `inverse_transform` 调用前增加维度一致性检查：`predictions.shape[-1] == self.preprocessor.mean_.shape[0]`。

**影响范围**: `python/app/ai/lnn/engine.py` 第493-495行

### 3.4 ManufacturingError 异常处理器注册

**问题**: `ManufacturingError` 异常虽有完整定义但未在异常处理器注册表中注册，抛出的异常被通用处理器捕获，丢失了结构化错误信息。

**修复**: 
- 新增 `manufacturing_error_handler()` 处理器函数
- 按severity分级日志输出
- 使用 `manufacturing_error()` 响应构建器返回结构化错误
- 在 `register_exception_handlers()` 中注册

**影响范围**: `python/app/core/exception_handlers.py`

### 3.5 通用异常处理器改进

**修复**: `generic_exception_handler` 重构：
- 使用 `logger.error` 代替 `logger.exception`，显式传递 `exc_info=True`
- 日志格式沉淀为结构化key=value模式
- 移除对已废弃 `InternalServerException` 的依赖，改用直接参数

**影响范围**: `python/app/core/exception_handlers.py`
