## 二、启动稳定性修复

### 2.1 WebView2 资源争抢问题修复

- **文件**: `src-tauri/src/lib.rs`
- **问题**: splashscreen 与 main 窗口同时创建 WebView2 实例时，两个 WebView2 争抢同一 EBWebView 用户数据目录，导致 `HRESULT(0x800700AA)` "请求的资源在使用中" 错误，主窗口创建失败或变为 15×15 像素空壳（白屏）。
- **修复方案**:
  - 将主窗口创建改为延迟模式：splashscreen 的 WebView2 先完成初始化（等待 500ms），之后再创建 main 窗口的 WebView2
  - 启动时主动清理 WebView2 残留锁文件（`LOCALAPPDATA/com.lingjing.manufacturing/EBWebView`），避免上次异常退出导致的 LOCK 文件阻塞
  - 新增 10 秒超时兜底机制：若前端 `close_splashscreen` IPC 未触发，自动强制显示主窗口并关闭 splashscreen

### 2.2 Splashscreen → 主窗口平滑切换

- **新增命令**: `close_splashscreen`（`src-tauri/src/commands.rs`）
- **机制**:
  - 前端 Vue 应用挂载完成、首屏渲染就绪后调用此命令
  - 先 `show()` 主窗口 → `set_focus()` 聚焦 → 再 `close()` splashscreen
  - 避免"先关 splash 再显主窗口"造成的视觉空档（白屏闪烁）
- **权限配置**: `src-tauri/capabilities/default.json` 新增 `splashscreen` 窗口声明及 `core:window:allow-show`、`core:window:allow-set-focus` 权限

### 2.3 index.html 预加载标签修复

- **文件**: `index.html`
- **问题**: `<link rel="preload" href="/src/main.ts" as="script">` 在 Vite 构建后被转换为 data URI，MIME 类型错误（`video/mp2t`），导致 `main.js` 无法执行、Vue 应用无法挂载
- **修复**: 移除该 preload 标签，保留 DNS 预解析和预连接配置

### 2.4 DevTools 支持

- **文件**: `src-tauri/Cargo.toml`
- **变更**: tauri 依赖新增 `devtools` feature，支持 release 模式下打开 DevTools 辅助排查白屏等前端问题

## 三、PyTorch 软依赖改造

### 3.1 改造背景

桌面 MVP 打包时通过 PyInstaller excludes 排除 torch 以减小安装包体积。此前 torch 为硬依赖，torch 不可用时整个后端无法启动。V2.5.0 完成 torch 相关模块的软依赖改造，使应用在无 torch 环境下降级运行而非崩溃。

### 3.2 LNN 模型包（`python/app/ai/lnn/models/__init__.py`）

- torch 版模型（`BaseLNN`/`TorchCFCModel`/`TorchLTCModel`/`TorchHybridLNN`）改为 `try/except ImportError` 软导入
- torch 不可用时，相关符号置为 `None`，numpy 版模型正常可用
- 新增 `_HAS_TORCH_MODELS` 标志位供上层模块判断

### 3.3 切削力预测模块（`python/app/simulation/cutting_force/`）

- **`__init__.py`**: `CuttingForcePINN`/`PINNLoss`/`ResidualBlock`/`predict_cutting_force`/`predict_cutting_force_batch` 改为软导入，新增 `_HAS_TORCH` 标志位
- **`predictor.py`**:
  - `import torch` 改为 `try/except ImportError`
  - `_load_model()` 在 torch 不可用时返回 `None`
  - `predict_cutting_force()` 在 torch 不可用时自动回退到 Kienzle 解析解，返回结果中携带 `warning` 字段说明降级状态

### 3.4 仿真集成层（`python/app/process_planning/sim_integration.py`）

- 导入 `_HAS_TORCH` 标志位，在切削力预测前检查 torch 可用性
- torch 不可用时跳过 PINN 推理，仅执行颤振稳定性分析（`predict_stability` 无 torch 依赖）
- 切削力结果缺失时使用空字典兜底，保证评分函数 `_calculate_score()` 可用

### 3.5 Sidecar 启动注入（`python/sidecar_main.py`）

- **JWT 密钥自动生成**: 启动时若 `LNN_JWT_SECRET` 未设置，自动生成随机密钥（与 `start_server.py` 模式一致）
- **nlopt/casadi stub 注入**:
  - cadquery 2.7.0 将 nlopt/casadi 声明为硬依赖，PyInstaller excludes 排除后导入 cadquery 会触发 `ImportError`
  - 注入 stub 模块，使 cadquery 可正常导入；实际调用求解功能时抛出 `RuntimeError` 给出明确提示

### 3.6 Numba 缓存兼容（`python/app/simulation/voxel_cutter/cutter.py`）

- **问题**: PyInstaller onefile 打包后源文件路径不存在于文件系统，numba 的 `cache=True` 报 "no locator available for file ..."
- **修复**: 检测 `sys.frozen` + `sys._MEIPASS`，仅在非冻结环境下启用 numba 缓存

## 五、Splashscreen 视觉升级

### 5.1 背景与配色

- **背景**: 从渐变色动画（`linear-gradient 135deg #0f0c29 → #1a1a3e → #24243e`）改为纯色深色背景（`#0e0d0c`，应用色板 `--bg-900`）
- **径向光晕**: 新增 `body::before` 伪元素，叠加三层径向渐变，营造银河深邃感
- **品牌色统一**: 所有 `#409EFF`（Element Plus 蓝）替换为 `#007aff`（Apple 品牌蓝），`#67C3FF` 替换为 `#66abff`

### 5.2 粒子星河背景

- **技术升级**: 从 CSS DOM 粒子（`.particle` + `@keyframes floatUp`）升级为 Canvas 2D 粒子系统（`Starfield` 模块）
- **自适应密度**: 根据窗口面积动态计算粒子数量（80-180 个），保证视觉密度一致
- **颜色分层**: 55% 品牌蓝 `#007aff`、25% 浅蓝 `#66abff`、13% 中蓝 `#2e8dff`、7% 白色闪烁星点
- **性能优化**: 使用 `requestAnimationFrame` 驱动，支持 `devicePixelRatio` 高清屏适配

### 5.3 Logo 与进度条

- **Logo**: 新增 `logoGlow` 呼吸光晕动画（`drop-shadow` 脉冲），替代静态阴影
- **进度条**: 新增 `box-shadow: 0 0 12px rgba(0, 122, 255, 0.5)` 发光效果
- **CSS 精简**: 合并 `@keyframes` 规则为单行格式，移除未使用的 `drawLine` 动画

## 七、兼容性说明

### 7.1 向后兼容

- 所有 torch 软依赖改造均保持向后兼容：有 torch 环境时功能完全不变，无 torch 环境时自动降级
- 切削力预测在 torch 不可用时回退到 Kienzle 解析解，结果中携带 `warning` 字段标识降级状态
- 仿真集成层在切削力结果缺失时使用空字典兜底，不影响颤振稳定性分析

### 7.2 打包兼容

- PyInstaller onefile 模式下 numba 缓存自动禁用，避免 "no locator available" 错误
- nlopt/casadi stub 注入确保 cadquery 2.7.0 在无优化器依赖时可正常导入

### 7.3 平台兼容

- WebView2 清理逻辑仅在 Windows 平台执行（`#[cfg(target_os = "windows")]`）
- 主窗口延迟创建逻辑仅在桌面平台执行（`#[cfg(desktop)]`）
