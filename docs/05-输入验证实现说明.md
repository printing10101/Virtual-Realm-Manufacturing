# 输入验证与数据清洗机制实现说明

## 概述

本文档描述了灵境制造系统中实现的全面输入验证与数据清洗机制。该机制确保所有用户输入在处理前经过严格验证，提升系统安全性和数据质量。

## 架构设计

```
请求 -> InputValidationMiddleware (全局中间件)
       -> 路由层验证 (各API端点)
       -> 自定义验证器 (业务逻辑)
       -> 业务处理
```

### 分层验证策略

1. **中间件层**: 全局过滤XSS、SQL注入、长度限制
2. **路由层**: 针对特定接口的验证逻辑
3. **业务层**: 材料、尺寸、公差等专业验证

## 使用方法

### 1. 全局中间件（已自动启用）

中间件已在 `main.py` 中注册，自动对所有POST/PUT/PATCH请求进行验证：

```python
# main.py
app.add_middleware(
    InputValidationMiddleware,
    skip_paths=["/health", "/docs", "/openapi.json", "/redoc"],
    max_length=1000,
    enabled=True
)
```

### 2. 在API端点使用验证函数

```python
from app.core.input_validator import validate_and_clean, MaterialValidator, SizeValidator, ToleranceValidator

@router.post("/example")
async def example_endpoint(request: SomeRequest):
    # 基础验证
    cleaned, err = validate_and_clean(request.user_input, field_name="user_input")
    if err:
        return error(code=ErrorCode.INVALID_REQUEST, message=err.message, detail=err.to_response())
    
    # 材料验证
    mat_err = MaterialValidator.validate(request.material)
    if mat_err:
        return error(code=ErrorCode.INVALID_REQUEST, message=mat_err.message, detail=mat_err.to_response())
    
    # 尺寸验证
    result, size_err = SizeValidator.validate(request.size)
    if size_err:
        return error(code=ErrorCode.INVALID_REQUEST, message=size_err.message, detail=size_err.to_response())
    
    # 公差验证
    tol_result = ToleranceValidator.validate(request.tolerance)
    if isinstance(tol_result, ValidationErrorDetail):
        return error(code=ErrorCode.INVALID_REQUEST, message=tol_result.message, detail=tol_result.to_response())
    
    # 业务逻辑...
```

## 验证规则详解

### 基础验证

| 验证项 | 规则 | 说明 |
|--------|------|------|
| 长度限制 | ≤ 1000字符 | 防止超长输入攻击 |
| XSS防护 | 12种模式检测 | 包括script标签、事件处理器、iframe等 |
| SQL注入 | 8种模式检测 | 包括SELECT/UNION/注释/WAITFOR等 |

### 材料名称验证

- **白名单机制**: 仅允许预定义的材料
- **支持材料**: 45钢、Q235、40Cr、304不锈钢、6061铝合金、TC4等
- **动态管理**: 支持运行时添加/移除材料

### 尺寸格式验证

- **格式**: `数字+单位`，如 `100mm`、`5.5inch`
- **支持单位**: mm, cm, m, inch/in
- **数值范围**: 0.001 ~ 10000 (可配置)
- **自动换算**: 统一换算为毫米

### 公差等级验证

- **范围**: IT6 ~ IT14
- **输入格式**: 支持文本(`IT7`)和数字(`7`)两种形式
- **标准化输出**: 统一返回 `{"grade": "ITx", "numeric": x}`

## 错误响应格式

### 统一错误响应结构

```json
{
    "code": 4001,
    "error_type": "xss_detected",
    "message": "输入包含不允许的内容格式",
    "field": "user_input",
    "suggestion": "请检查并移除可能包含的脚本标签或特殊代码内容",
    "detail": "输入内容不符合安全规范"
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | HTTP标准错误代码 |
| error_type | string | 错误类型标识 |
| message | string | 用户友好的错误描述 |
| field | string | 出错的输入字段 |
| suggestion | string | 建议的修正方案 |
| detail | string | 详细错误信息(可选) |

## 扩展指南

### 添加新的验证器

1. 在 `input_validator.py` 中创建验证器类:

```python
class CustomValidator:
    @classmethod
    def validate(cls, value: str) -> Optional[ValidationErrorDetail]:
        if not is_valid(value):
            return ValidationErrorDetail(
                code=ErrorCode.INVALID_REQUEST,
                error_type="custom_error",
                message="验证失败描述",
                field="custom_field",
                suggestion="修正建议"
            )
        return None
```

2. 在API端点中使用:

```python
err = CustomValidator.validate(request.custom_field)
if err:
    return error(code=ErrorCode.INVALID_REQUEST, message=err.message, detail=err.to_response())
```

### 添加验证装饰器

```python
def validate_custom(field_name: str = "custom_field"):
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            value = kwargs.get(field_name)
            if value:
                err = CustomValidator.validate(value)
                if err:
                    raise HTTPException(
                        status_code=status.HTTP_400_BAD_REQUEST,
                        detail=err.to_response()
                    )
            return await func(*args, **kwargs)
        return wrapper
    return decorator
```

## 安全建议

1. 定期更新XSS和SQL注入模式库
2. 生产环境启用输入日志记录以便审计
3. 限制材料白名单的管理权限
4. 监控验证失败频率以检测潜在攻击

## 常见问题

**Q: 如何临时禁用验证?**
A: 修改 `main.py` 中的 `enabled=False`，但不建议在生产环境这样做。

**Q: 验证失败会记录日志吗?**
A: 当前版本不会记录验证失败日志，可以在中间件中添加日志记录。

**Q: 如何添加新的支持单位?**
A: 在 `VALID_UNITS` 字典中添加新单位及其换算因子。

**Q: 材料白名单在哪里维护?**
A: 白名单定义在 `input_validator.py` 中，可通过API动态修改。
